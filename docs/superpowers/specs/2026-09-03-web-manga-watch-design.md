# 仕様書：WEBマンガウォッチ

## 1. 目的

「WEBマンガウォッチ」は、複数の公式WEB漫画サイトに掲載されている作品の新話公開をひとまとめに確認できる一般公開Webサービスである。

副次的に、作品名・作者名・掲載サイト名で作品を検索し、新しい作品を発見できるようにする。漫画本文や画像は保存・配信せず、各公式サイトへ誘導する。将来的には通知機能を追加し、更新の見逃し防止へ拡張する。

### MVP対象作品

- 『ふたりバス』— 公式配信先：サンデーうぇぶり。更新検知はNDL Search APIを第一候補とし、必要な掲載メタデータが得られない場合のみ、利用条件を確認済みの公式メタデータHTML取得へフォールバックする。
- 『妹は知っている』— 公式配信先：ヤンマガWeb。ヤンマガWeb本体・コミックDAYSは取得せず、ヤングマガジン公式サイト（`magazine.yanmaga.jp`）の公開メタデータPoCを更新検知候補とする。

### 成功条件

- 対象2作品の新話または新号掲載を重複なく検出できる
- 利用者が登録なしでフォローと既読管理を始められる
- 公式配信ページへの導線を提供できる
- 単行本のKindle版・紙版へのAmazonリンクを表示できる
- MVPの更新検知に有料APIを必要としない

## 2. MVPの範囲

### 含める機能

- 未ログインでの作品・作者・サイト検索と閲覧
- Cookieによる匿名利用者管理
- 漫画・作者・掲載サイトのフォロー
- フォロー対象の更新一覧
- 更新話の自動既読化と手動での未読戻し
- 作品名・作者名・サイト名による検索
- 作品詳細でのKindle版・紙版Amazonリンク
- 1日1回の更新取得
- NDL Search API、公式RSS、利用条件上許容された公式メタデータHTMLからの更新検知

### MVPに含めない機能

- 会員登録・ログイン
- メール通知・Webプッシュ通知
- ランキング、レビュー、コメント
- 運営者向け管理画面
- ユーザーによる任意サイト追加
- 漫画本文・画像の保存または配信
- X API等の有料APIを前提とする更新取得

## 3. 技術構成

- フロントエンド：Next.js 16 + vinext
- ホスティング・実行基盤：Cloudflare Workers
- データベース：Supabase PostgreSQL
- 定期処理：Supabase CronからEdge Functions等をスケジュール実行
- 利用者識別：個人情報を含まないランダムな匿名ID Cookie
- 更新取得：無料で利用可能な公的・公式メタデータ源を優先
- 開始時のプラン：Supabase Freeを基本とする

利用者増加だけを理由に有料化せず、容量、通信量、バックアップ、安定運用の必要性を見てProへ移行する。

## 4. データモデル

### Site

配信先・閲覧先を表す。更新検知元とは分離する。

- id
- name
- base_url
- enabled

### UpdateSource

作品ごとの更新検知元を表す。

- id
- series_id
- source_type（`ndl_sru`、`rss`、`html_metadata`）
- source_identifier
- priority
- enabled
- last_fetched_at
- last_success_at
- last_fetch_status
- last_error
- last_episode_count
- consecutive_failures

取得優先順位は原則として `ndl_sru` → `rss` → `html_metadata` とする。`html_metadata` は利用規約・robots.txt・アクセス制限等を確認し、利用条件上許容された場合のみ有効化する。

NDL Search APIの作品名検索は単行本レコード中心であり、掲載号や新話タイトルを直接返すとは限らない。雑誌名検索の結果は関連商品・単行本等が混在するため、作品掲載を確実に判定できない場合は更新取得元として有効化しない。

### Author

- name
- normalized_name
- created_at

### Series

- id
- title
- site_id
- series_url
- description
- thumbnail_url
- update_day
- kindle_asin
- paperback_asin

### SeriesAuthor

- series_id
- author_id
- role

### Episode

- id
- series_id

- first_detected_at
- is_promotional

`source_episode_key` は更新取得アダプターが生成する取得元固有の安定キーとし、`UNIQUE(update_source_id, source_episode_key)`で重複を防ぐ。URLは変更される可能性があるため、同一話の識別子そのものにはしない。

NDL Search API等で話数・話タイトルまで取得できない場合は、雑誌号・発売日等の確実に取得できる情報だけを保存し、不明な値を推測しない。

- updated_at

## 5. 更新取得仕様

1. 1日1回、`UpdateSource`単位で取得処理を実行する。
2. 更新検知元と公式配信先を分離し、取得元がNDL等でも、利用者には公式配信ページへの導線を提供する。
3. 第一候補はNDL Search API（SRU/OpenSearch等）とする。
4. NDLで必要な掲載メタデータが取得できない場合、公式RSSを使用する。
5. RSSもない場合のみ、利用条件上許容された公式メタデータHTMLを低頻度で取得する。
6. 自動取得を禁止するサイトにはHTMLアダプターを実装・有効化しない。
7. X API等、有料利用を前提とするAPIはMVPの取得元に採用しない。
8. `source_episode_key`で既存話と照合し、未登録の更新だけを新規登録する。
9. NDL等で「雑誌掲載」までしか判定できない場合は、雑誌号・発売日を更新単位として登録する。話数や話タイトルを推測しない。
10. 1つの公式URLに複数話が含まれる場合は、話表示名を`episode_label`として保持する。
11. PR、単行本告知、キャンペーン、投票、お知らせは本編更新から除外する。
12. 公開終了した話は履歴から削除しない。
13. 取得失敗時は既存データを変更せず、更新取得元単位でエラーを記録する。
14. HTTP 200でも前回の取得件数から不自然に0件になった場合などは異常と判定し、成功扱いにしない。
15. HTML取得を行う場合はアクセス頻度を低く保ち、利用規約・robots.txt・アクセス制限を尊重する。

### MVP取得方針

#### 『妹は知っている』

- 第一候補：NDL Search APIでヤングマガジン各号の掲載情報を確認する。
- 作品名、作者名、発売日、号情報等、NDLレスポンスに存在する確実なメタデータのみ使用する。
- ヤンマガWeb・コミックDAYS等、自動取得を禁止している配信サイトは取得元にしない。
- 公式配信ページURLは閲覧導線として保持するが、更新判定のためにクロールしない。

#### 『ふたりバス』

- 第一候補：NDL Search APIで週刊少年サンデー各号の掲載情報が十分な粒度で取得できるか検証する。
- NDLだけで作品掲載を安定判定できない場合は、既存のSundayWebryProbeを技術検証用に維持する。
- SundayWebryProbeはfixtureテストと必要時の手動live probeに限定し、定期クロール、CIからのlive access、ユーザー向け更新通知には使用しない。
- SundayWebryAdapterの本番化には、小学館へ継続的な自動取得・メタデータ利用の許諾を確認することを必須条件とする。
- 許諾確認前は漫画本文・画像を保存せず、取得処理を本番環境で有効化しない。

## 6. 利用者体験

- 初回アクセス時に匿名ID Cookieを発行する。
- Cookieにはフォロー情報や個人情報を直接保存しない。
- 更新話への公式リンクをクリックした時点で既読にする。
- 既読話には手動で未読へ戻す操作を用意する。
- Cookie削除、別ブラウザ、別端末では状態を引き継がない。
- 180日間アクセスがない匿名利用者のフォロー・既読データは削除対象とする。
- 将来ログインを追加する場合は、匿名データをアカウントへ移行できる構造にする。
- 既読化リクエストは`navigator.sendBeacon`または`fetch(..., { keepalive: true })`で送信し、公式ページへの遷移でリクエストが失われにくくする。

## 7. Amazonアフィリエイト

作品詳細ページに、作品ごとに手動登録したAmazon商品情報を表示する。

- Kindle版へのリンク
- 紙の単行本へのリンク
- 必要に応じて既刊・最新巻へのリンク

初期はASINを開発者が登録する。価格や在庫を自サイトに固定表示せず、Amazonの商品ページへ誘導する。アソシエイト承認後にタグ付きリンクを有効化し、サイト内にAmazonアソシエイトである旨を明示する。承認前は通常リンクまたはリンク非表示とする。

Amazonの利用規約・プログラムポリシーに従い、商品画像・価格・商品情報の利用方法は実装前に最新条件を確認する。

## 8. 画面構成

- トップページ：サービス説明、最新更新、検索、作品発見
- 更新一覧：フォロー中の更新、未読・既読、更新日順
- 作品詳細：作品情報、作者、掲載サイト、話一覧、フォロー、Amazonリンク
- 作者詳細：作者の作品とフォロー
- サイト詳細：掲載作品とフォロー
- マイページ：匿名利用者のフォロー一覧、未読一覧、既読管理
- 固定ページ：利用規約、プライバシーポリシー、アフィリエイト開示

## 9. テスト方針

- NDL取得アダプターの単体テスト：固定SRU/OpenSearchレスポンスを使い、作品名、作者名、号、発売日、重複キー、欠損値を検証する。
- RSS取得アダプターの単体テスト：固定RSSを使い、タイトル、日時、URL、除外対象を検証する。
- HTML取得アダプターの単体テスト：固定HTMLのみを使い、話数、タイトル、日時、URL、除外対象を検証する。
- SundayWebryProbeのlive probeは必要時の手動確認に限定し、自動テストやCIでは実行しない。
- 差分検出の単体テスト：新規、重複、URL変更、取得失敗、0件異常を検証する。
- NDLで話数・話タイトルが欠けるケースでも、推測値を生成しないことを検証する。
- DB/APIの統合テスト：フォロー、既読化、未読戻し、匿名ID分離を検証する。
- 画面のE2Eテスト：検索、フォロー、更新確認、公式リンク遷移を検証する。
- 定期処理の動作確認：有効な`UpdateSource`のみ取得し、エラー記録、再実行、フォールバック判定を確認する。

## 10. 運用・セキュリティ境界

### 常に行う

- 無料かつ利用条件が確認できた取得元を優先する
- 更新取得元と公式配信先を分離する
- 外部レスポンスを信頼せず、取得値を検証・正規化する
- CookieにSecure、HttpOnly、SameSite等の適切な属性を設定する
- 漫画本文・画像を保存しない
- 取得エラーと最終成功日時を記録する
- 前回件数、今回件数、連続失敗回数を記録する
- 0件化などの構造変化を異常として検知する
- 規約・プライバシー・アフィリエイト開示を公開する

### 事前に確認する

- NDL Search APIのデータ提供元ごとの利用条件。広告・アフィリエイトを含む営利利用で申請が必要な場合は、一般公開前に必要な手続きを行う。
- HTML取得対象サイトの利用規約・robots.txt・アクセス制限
- Amazonアソシエイト申請とリンク表示条件
- 独自ドメインの取得
- Supabase FreeからProへの移行
- 新しい対応サイト・更新取得元の追加
- HTML解析処理の変更

### 行わない

- X API等の有料APIをMVP取得基盤として採用する
- 自動取得を禁止する配信サイトへのクローリング
- ユーザーが指定した任意サイトの無制限クロール
- ログインが必要なページの取得
- 漫画本文・画像の転載
- Amazonの商品情報の無許可な長期キャッシュ
- 秘密情報、パスワード、APIキーのリポジトリ保存

## 12. 取得対象の制約

取得アダプターは、NDL Search API、公式RSS、または利用条件上許容された公式メタデータ取得手段のみ実装する。自動取得を禁止するサイトにはHTMLアダプターを実装・有効化しない。有料APIはMVPでは採用しない。

### SundayWebryのDisposition

- `SundayWebryProbe`：技術PoCとして維持
- fixtureベースの自動テスト：維持
- 手動live probe：必要時のみ実行
- 定期クロール・CIからのlive access：禁止
- `SundayWebryAdapter`：小学館の許諾確認まで未実装・未有効化
- ユーザー向け更新通知への利用：許諾確認まで禁止

本番Adapter化の条件は、`TECHNICAL_PASS && TERMS_PASS`とする。規約確認だけで継続的自動取得が許容されると推測せず、小学館へ利用目的、取得項目、頻度、キャッシュ期間、本文・画像等を保存しないことを明示して許諾を確認する。

NDL Search APIを一般公開・収益化環境で利用する場合は、対象レコードのデータ提供元と営利利用条件を確認し、必要な申請がある場合は公開前に完了させる。

## 14. 取得元候補のDisposition

### となりのヤングジャンプ

- グローバルAtom／RSSは現行公開導線として確認済み
- 作品単位Atom/RSSは公開導線および合理的なslug候補から確認できなかった
- 対象2作品はグローバルAtomに含まれない
- 作品名フィルタPoCは作成しない
- `TonariNoYJAtomProbe`は候補を見送り、必要なら将来再調査する
- 非公開API探索、総当たり、HTML fallbackは行わない

### ヤングマガジン公式サイト

- `magazine.yanmaga.jp`のトップページから『妹は知っている』の作品名、作者、話タイトル、公開日、コミックDAYSへの公式リンク文字列を確認できる。
- 取得元へのGETは`magazine.yanmaga.jp`だけに限定し、コミックDAYSへはアクセスしない。
- `YanmagaMagazineProbe`はfixtureと必要時の単発live probeに限定する。
- 0件、必須メタデータ欠損、想定外リンクホストは更新なしではなくfailureとする。
- 本番Adapter化、定期実行、ユーザー向け通知への利用は、講談社の利用条件確認まで保留する。
